Each row is a complete path with its own review/checkpoint. Stable V3a/V3b/V5/V6 identifiers are retained; sub-slices clarify dependencies rather than pretending later behavior already exists. **Formation + linked recovery + early inline activation form the first useful complex-project delivery gate, not one giant implementation change.**

V3a1 is a useful small-project increment; do not call the complete Vivarium experience delivered until V5a/V3b1 pass. Pull attachment/update before advanced template packs so externally revised plans and ordinary local correction are practical, while new-project and existing-project formation remain separately testable paths. The full scope terminal editor is not a prerequisite for the first four-stage plan, but all supported initial commands still enforce terminal/revision guards.

## Approval and verification gates

1. Review D1–D5 and Antigravity's independent UX critique. No V3 implementation begins from this design package alone.
2. For the next authorized slice, specify exact additive tables/constraints, command DTOs, revisions, source ownership and failed/acknowledged-write behavior. Obtain concrete migration approval; never edit 001–003. Do not create future rule/evidence/snapshot tables speculatively.
3. Rerun the actual existing baseline before code. Every persistence slice needs a consistent backup and populated-v3 preservation fixture: legacy backlog completion/history, checkpoints, workflow origins, active and frozen releases; migration rollback/FK/newer-schema refusal, exact before/after equality and packaged restart. Isolated profiles only.
4. Test pure rules/store transactions, then a real renderer → typed bridge → main → SQLite path. Cover cancelled/stale review, source replacement, duplicate Apply, transaction abort, command failure, acknowledged success + failed refresh, read-only retry and navigation races. Continue never repeats a command just to refresh.
5. Run actual Node/Electron/build and relevant rebuilt packaged recovery, then compact/wide keyboard/error/empty/large-project checks. Report execution separately from static checks and user acceptance. Maintain checklist/verification/short Obsidian checkpoint and relevant new ADRs only after decisions are accepted.

Deterministic recommendations are absent initially because no approved rule catalog/prerequisite semantics or evaluator exists. Saved next steps, chosen focus and explicit authored organization are enough to start honestly. PTB priority/dependency/schedule extensions, development percentages, Git/Obsidian product integration, local models, developer personalization, pattern recognition, workflow sync, conditional packs and automatic agents remain deferred. Their absence must be clear, without fake controls.

The current [Antigravity V3 handoff](../agent-handoffs/antigravity-v3-workspace-design.md) is independent **design only**. Committed reports and explicit Git refs carry feedback; no assumed live communication, source overlap or automatic implementation permission.
