## Every implementation gate

- Rerun actual baseline before approved code. Main owns named commands/validation/IDs/times; renderer sends reviewed choices, not authoritative graphs/SQL/paths.
- Before a numbered migration, approve concrete keys/constraints/DTOs/revisions and consistent backup/rollback. Never edit 001–003. Test populated-v3 exact equality: legacy IDs/text/times/completion, events/checkpoints, templates/origins, active and frozen releases/verification/confirmation. Keep newer-schema refusal/FK checks and isolated profiles.
- Exercise atomic failure at each apply/membership/history/receipt boundary, duplicate/stale review, changed capture/target, uncertain acknowledgement, acknowledged success plus failed refresh, repeated read-only retry and navigation/layout races.
- Verify production CSP/app:// and ASAR with the actual locked UI libraries before shipping. Prototype success does not justify unsafe-eval/inline/network/worker relaxations. Bound layout/query work; cancellation/stale results and accessible list remain available.
- Run actual Node/Electron/build and relevant rebuilt packaged recovery for a production/persistence slice; inspect wide/narrow, keyboard/focus, empty/error/large content and source safety. Report real outcomes/manual limits separately.
- Update checklist/verification/short Obsidian checkpoint and relevant new ADRs after approved decisions; preserve old history. One integration owner, exclusive agent files, committed report refs, no premature merge.

Defer date-aware Gantt, dependency editor/critical path, progress percentages, AI/model runtime, Git integration, vault adapters, personalization/settings, automatic workflow synchronization and cross-project learning. Their purpose/prerequisites/horizon are recorded in the dedicated backlog. Stop before any production slice until reviewed.
