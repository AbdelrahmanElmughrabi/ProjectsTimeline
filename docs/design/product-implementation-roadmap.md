## Design and schema gates

V2 contract/order/parser directions and shared types are finalized in Phase A; installation/runtime work waits for actual handoff confirmation and explicit gate opening, then Codex BEGIN. Verify combined lock/integrity, packaged ESM and acquisition/security behavior in Phase B. Before V3a: specify exact additive tables/keys/guards/DTOs, including uncommitted-action protection and source receipt idempotency; obtain SQL design approval before a new numbered migration. Before V3b/V4: review concrete scope/template key/purpose schema under the approved domain; expose truthful counts/Not Assessed until a separate development percentage policy is approved. Never edit 001–003 or create later snapshot/evidence/rule tables prematurely.

Every persistence slice needs populated-v3 golden state (active and confirmed releases, templates, backlog completion, checkpoints/history), consistent backup, migration rollback/FK/newer-schema refusal, exact before/after comparisons and final packaged restart. Use temporary profiles; no production database mutation for testing.

Before code, rerun actual existing baseline. After each slice, run appropriate Node/domain/store and real Electron success/error/keyboard/compact checks; build/package and run packaged recovery for changed persistence paths. Include failed command, acknowledged command plus failed refresh, repeated read retry, stale revisions, duplicate apply and superseded navigation. Report actual outcomes separately from manual acceptance and from design-fixture checks.

Keep README/checklist/roadmap/verification/concise Obsidian checkpoint and relevant **new** ADRs current after approved decisions; preserve older ADRs as history. One integration owner coordinates migrations/shared contracts. The [Antigravity prompt](../antigravity-collaboration-prompt.md) remains review-first; implementation requires an assigned approved slice and isolated checkout/file ownership. Do not initiate implementation agents during this phase.

Deterministic recommendations are deliberately absent initially: no approved/implemented rule catalog or recommendation evaluator exists, so V1 shows only saved next steps and actual activity. Keep suggestion generation/adoption as V6b, separate from explicit PTB proposals and baseline development work. Git/Obsidian product integrations, local models, personalization, pattern recognition, automatic agents, workflow sync and conditional rules remain future proposals. The reference guides continuity, not fabricated controls/data.
