## Critical trust boundary discovered in the current code

BlueprintPreviewSession currently retains a **file grant**, not an authoritative cached validated snapshot/formation receipt. Before any Apply feature, main must retain the exact reviewed capture/plan by opaque ID (or an equivalently approved immutable main-owned capture). Do not trust a renderer-supplied graph, or reread current disk bytes and pretend they are the reviewed source. Preview/cancel still writes nothing. Refresh/expiry retires review plans; exact completed receipt recovery precedes rejection of a consumed/expired token for an identical retry.

Future command names are tentative: prepare/apply reviewed formation, get development workspace, adopt reviewed work, save linked checkpoint, activate development scope. Add only the named methods needed for the authorized slice, through the current trusted sender/frame/URL and Result validation. No generic graph mutation/SQL/file channel. A future MCP transport could call these same domain operations after its own explicit authorization policy; it must not expose Electron IPC or filesystem grants indiscriminately. No MCP server/SDK/dependency is authorized now.

Preserve type distinctions in that boundary: preview occurrence/document/source identities versus bound external PTB identities versus internal project/entity/action IDs. Do not coerce source IDs into existing integer action APIs. Invalid/duplicate occurrences remain source inspection, not canonical entities chosen by a renderer Map's last-wins behavior. Formed graph operations require stable same-project bindings and expected revisions.

## Required acceptance gates

1. **Preview:** valid/invalid/partial-invalid capture, exact source/null source, cancellation/refresh/source change; no durable writes/model calls. PTB 0.1 rejected as unsupported, not silently converted.
2. **Formation:** new target/binding/graph/source/receipt/history in one transaction; fault each phase; duplicate/uncertain acknowledgement returns one result; no renderer-authoritative data or partial project. Confirmed releases/legacy actions/checkpoints/templates exactly preserved after migration/restart.
3. **Adoption:** requirement-only, scope-only, unscoped action-only, mixed placements, still-Draft requirements with/without explicit acknowledgement, scoped target not activated, invalid/missing/stale/cross-project references, unresolved/terminal plans, repeated/no-op/reopened review, cancellation and failed refresh. Current commitments cannot be removed by clearing selections.
4. **Map:** selection preserves positions/viewport; correct source assertions/path distance; source and generated views distinct; bounded expansion/layout failure/stale job; outside-lens and explicit-null placement; keyboard/search/outline/source-return and narrow detail/list legibility.
5. **Continuity:** browsing another record does not silently change intended checkpoint target; restore validated target/view/lens/filter or explain fallback; preserve exact old journal ordering and authored text; actual packaged restart. No focus/session inferred from viewing source.

No test in AG's isolated harness exercises these database transactions, migrations, real IPC or packaged restart. Production Node/Electron/build/package verification must be run when the corresponding slice is actually implemented; screenshots and an absent app bridge cannot replace it.
