## Three concepts reviewed; final recommendation

**A — Component Atlas:** stable-map intent and one right inspector are useful; the ownership hub spokes repeat the project header and consume canvas space. They come from real project fields, but add little engineering understanding. Retain research, omit the hub by default.

**B — Focus Workbench:** capability-first navigation helps, but its index/map/lower inspector compresses the canvas and competes for scrolling. Reject as the default production layout; keep its useful capability-directory idea.

**C — Spoke-Free Atlas (AG):** clearest structural index and right inspector, with outside-lens recovery and a neighborhood return path. Recommend a **refined C**, not wholesale adoption of its implementation. Its default has seven component cards and no typed edges: call this a component index/atlas, not a runtime dependency topology. Source-backed connected neighborhoods supply the relationship map. Reduce columns/use a list at narrow sizes; ordinary selection must preserve spatial orientation.

Keep explicit edge segments solid/source-labelled even when two steps from the anchor. Display a derived route separately, with both constituent edge IDs and its via feature; path distance is not assertion origin, confidence, prerequisite or evidence. A neutral “No explicit feature links” describes sparse source data, not an engineering defect.

[The consolidated review](v3-consolidated-review.md) records actual source/state/layout/focus problems and the A/B/C comparison. Antigravity's 5,319-line change remains isolated at 92a7129. No branch merge, source copy, migration or feature implementation occurs during this review. The original and AG studies are simulated research; neither defines production behavior merely by rendering it.

## Connected interaction contract

1. **Home:** recognizable projects; actual saved intention if present. No checkpoint means Open project and a small Save checkpoint affordance later, not an empty dominant Resume panel. Recorded app activity is labelled Recorded; actual verified outcomes have separate evidence provenance.
2. **Landing/Overview:** a new preview opens the human summary; after durable formation, Open workspace can lead to Map with Overview explicitly reachable. Legacy project entry stays working. No new active-project flag is invented solely for landing. Goal and major capabilities/components first, explicit current focus and unresolved questions only when authored. Counts use explicit qualifiers: proposed/committed/in progress/done/Not assessed. No invented percent, schedule, highest priority or coding session.
3. **Map (primary visualization):** component/feature structure, bounded expansion, selection, drag, pan/zoom/fit, semantic lenses/search/list. Relationships show their meaning, direction and source; layout/line proximity never imply dependencies. Default excludes actions, decisions and checks. Requirements enter only contextual neighborhoods; the inspector links other engineering records.
4. **Inspector/source:** same durable identity across views; purpose/details/links first, IDs/hashes secondary. Exact captured section is available and inert. A related-through-feature item is labelled as a path, not a new asserted dependency. Definition/source assertions are not verification.
5. **Development (secondary):** authored scopes/stages and linked capabilities/work. No dates → ordered roadmap; date-aware Gantt remains a later explicit-data feature. Plans, explicit commitments/current work and actual completion are separate. Out-of-order work remains legal. Nothing confirms a release or passes a check from an ordinary completion control.
6. **History/continuity:** actual imports/adoptions/changes/checkpoints/accepted decisions/observations when those operations exist. Source narrative is not historical execution. Save authored accomplishment/problem/questions/next step with an explicit target: default to intentionally chosen focus or project; Use selected record is deliberate. Merely browsing cannot silently change the saved work target. Continue resolves validated target/view/lens/filter hints; missing/stale targets retain text and offer history/current context.
7. **Blueprint adoption:** human summary → explicit target → grouped requirement acceptance/action commitment/scope activation with default none → final effect summary → atomic apply/receipt. All definitions survive as proposals without 47 manual forms. Existing-project attachment and updates remain separately reviewed paths; no fuzzy matching/overwrite.
8. **Local evolution:** change a local working definition through a revision, preserve original source, review later source changes against the prior baseline. Map-node movement only arranges the view. It never reassigns a feature, adds a dependency or changes action progress. No edge creation/semantic deletion by dragging in the first map slice.
